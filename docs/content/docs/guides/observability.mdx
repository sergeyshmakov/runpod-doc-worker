---
title: Logging and diagnostics
description: Add job-correlated stdout logs, compact failure text, and bounded worker diagnostics to a RunPod handler.
---

The observability modules write directly to stdout and expose diagnostic data for a handler to compose. They do not install a handler or automatically answer probe jobs.

## Correlate logs with a job

Set and reset `job_id_var` around each job:

```python
from runpod_doc_worker.obs import logging as worker_logging

token = worker_logging.job_id_var.set(job_id)
try:
    worker_logging.info("processing started", source_kind="b64")
finally:
    worker_logging.job_id_var.reset(token)
```

The default output is one JSON object per line. Set `LOG_FORMAT=text` for compact local output. Set `LOG_LEVEL=debug` to enable calls to `debug()`; this variable does not filter the other levels.

The public emitters are `info()`, `warning()`, `error()`, and `debug()`. Caller fields cannot replace `ts`, `level`, `logger`, `msg`, or `job_id`.

## Mirror records to another sink

Set `WorkerConfig.log_mirror` to a callback with the signature `(level, message, fields)`. Stdout is written first. If the mirror raises, the worker emits a warning and continues the job.

```python
def mirror(level: str, message: str, fields: dict) -> None:
    telemetry_client.write(level, message, fields)
```

## Compact failure text

Use `compact()` before returning exception text to a caller:

```python
from runpod_doc_worker.obs.redact import compact

safe_message = compact(str(exc))
```

The helper removes credentials, query strings, and fragments from URLs and limits output length. It does not remove arbitrary API keys, tokens, or every secret that may appear in a message.

## Collect diagnostics

```python
from runpod_doc_worker.obs import debug

diagnostics = {
    "gpu": debug.collect_gpu_info(),
    "model_dir": debug.find_model_dir(),
}

if caller_is_operator:
    diagnostics["filesystem"] = debug.probe_filesystem()
```

`collect_gpu_info()` inspects device 0 when Torch is available. Missing Torch and inspection errors are returned as data.

`find_model_dir()` searches the effective Hugging Face Hub cache using `model_globs`. It reports a recent matching cache directory, not proof of which model weights handled a job.

`probe_filesystem()` performs bounded, read-only, network-free scans and answers whenever it is called. Results can include partial-scan markers when a limit is reached.

<Callout type="warn" title="Keep diagnostics behind an operator boundary">
  Filesystem diagnostics expose cache paths and selected environment values. Do not return them to untrusted callers.
</Callout>

## Deciding who may ask is yours

This package reads no probe environment variable and has no probe policy. `probe_filesystem()` returns the dump to whoever calls it.

That is deliberate. Whether a caller may see worker-local paths and declared env values depends on who a worker's callers are — a single-tenant endpoint and a shared one want opposite answers, and only the worker knows which it is. While this package guessed, the name and the default of an operator-facing knob moved twice in two releases, under endpoints already deployed with the old spelling.

So the worker owns the gate: it names the variable its operators set, picks the default its deployment wants, and calls this function once it has decided. Nothing here can move that out from under it.

### Migrating from 0.4.x

`probe_enabled()` and `WorkerConfig.probe_default` are gone, and `<PREFIX>_ENABLE_PROBE` and `<PREFIX>_DISABLE_PROBE` are no longer read here. A worker that relied on either — including on `probe_filesystem()` raising `PermissionError` — implements the gate itself, keeping whatever variable name its operators already have:

```python
import os

_TRUTHY = ("1", "true", "yes", "on")


def _probe_allowed() -> bool:
    """Whatever this endpoint's operators already set. The name is yours."""
    return os.environ.get("ACME_DISABLE_PROBE", "").strip().lower() not in _TRUTHY


if job_input.get("probe") is True:
    if not _probe_allowed():
        raise ValueError("probe is disabled on this endpoint")
    return {"probe": debug.probe_filesystem()}
```

Keeping the old variable name is the point: an operator's existing setting keeps meaning what it meant, and it stops being a name a dependency can change.

Use [worker configuration](/docs/getting-started/configuration/) to select cache patterns and probe fields.
